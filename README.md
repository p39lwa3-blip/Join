# CT小舖交易 Bot V10

獨立交易 Bot。**不修改、不取代原本 Ticket Bot。**原 Ticket Bot 負責建立工單，本 Bot 只偵測 `ticket-數字` 並在工單內提供交易流程。

## 客人流程
1. 原 Ticket Bot 建立 `ticket-0015`。
2. 本 Bot 等 1 秒發交易面板，再等 1 秒改成 `工單-0015`。
3. 客人按商品 → Discord 彈出原生輸入框，直接輸入購買數量並送出。
4. 有足夠現貨：直接進付款方式。
5. 沒有足夠現貨：詢問是否接受 `/設定交貨時間` 設定的統一交貨時間；接受後進付款方式。
6. 選「無卡存款」或「匯款（轉帳）」後顯示對應付款資訊。
7. 客人按「💳 完成付款」後進入 `待交貨`。

## 老闆端新增功能
- 客人選擇付款方式後，工單狀態頻道立即建立訂單卡，顯示商品、數量、總價、客人、狀態、付款方式、交貨時間。
- 狀態卡提供管理員按鈕：`🛠️ 開始處理` → `📦 完成交貨` → `✅ 完成訂單`，並附 `🎫 前往工單`。
- 每次狀態操作會更新同一張狀態卡並寫入操作紀錄。
- 待付款逾時提醒：預設 15 分鐘提醒一次，可用 `/設定付款提醒` 設定，填 0 關閉。
- `/今日統計` 查看當日訂單數、金額與各狀態。
- 防止快速連點造成同一張工單重複建立訂單。

## 工單改名
工單名稱**不再包含客人名字**。格式為：`狀態-工單號-商品數量`，例如：`待付款-0015-100M二隻`、`結單-0015-100M二隻`。前導 0 保留。

## 工單辨識
只有頻道名稱**完全符合** `ticket-數字` 才會被視為新工單。`工單-0015`、`結單-0015`、`closed-0015` 等改名後頻道不會重新觸發。

## 部署
1. ZIP 解壓後上傳 GitHub。
2. Railway Variables 設定 `DISCORD_TOKEN`。**不要把 Token 寫進程式或 GitHub。**
3. `Procfile`：`web: python bot.py`。
4. 建議 Railway 使用 Volume 掛載 `/data`，讓 SQLite 的價格、庫存、訂單與設定持久保存。
